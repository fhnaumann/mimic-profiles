Terminology mappings were separated into _streams_. A stream consists of a source-code enumeration, a single mapping method, and one or more permitted target terminology systems. The same stream may be reused by several FHIR elements, ensuring that a source code is mapped consistently wherever it occurs.

A source enumeration was obtained either from an entire CodeSystem or from a ValueSet. An entire CodeSystem was used when all its concepts received the same mapping treatment. For example, the `mimic-medication-name` CodeSystem formed one stream even though its codes were consumed by several medication-related elements.

ValueSet enumerations were used in two situations. First, they represented bounded subsets of an external standard terminology. For example, the ED Observation, vital-sign Observation, and vital-sign component ValueSets enumerate distinct subsets of LOINC without requiring local copies of the complete LOINC CodeSystem. Second, they partitioned a local CodeSystem into semantically distinct populations. The `mimic-d-items` CodeSystem, for example, is used by three FHIR profiles: one Procedure profile and two Observation profiles. The existing `mimic-procedureevents-d-items`, `mimic-datetimeevents-d-items`, and `mimic-outputevents-d-items` ValueSets contain 169, 188, and 77 codes, respectively. The subsets do not overlap, and their union contains all 434 concepts in `mimic-d-items`.

Each stream then specifies one mapping method. Identity mappings were used when the source coding was already expressed in the intended standard terminology. These mappings were included explicitly so that already-standard codes were represented in the generated ConceptMaps. Deterministic notation transformations were used for ICD diagnosis and procedure codes. The transformed codes were checked against the locally built ICD release resources before inclusion.

Source populations for which no deterministic transformation was available were mapped using committed mapping tables. Depending on the stream, these tables contained targets from LOINC, SNOMED CT, RxNorm, or UCUM. A stream could permit more than one target system; in such cases, the target system was selected separately for each source code. The resolved streams were subsequently combined into element-level ConceptMaps and their corresponding target ValueSets.

Stream membership was determined from the IG’s CodeSystem and ValueSet definitions, rather than from observed data. Warehouse occurrence data was used subsequently to identify which enumerated source codes occurred in MIMIC-IV. Streams sharing a source system were checked for overlapping `(system, code)` pairs, and the combined stream enumerations were checked against the ValueSets used by the inventoried FHIR elements.

In total, 28 streams were defined: four notation-transformation streams, six identity streams, and 18 table-based streams. These streams were combined into 11 element-level ConceptMaps.
